# Takahashi adjustment rule record

## Identity and basis

- ID: `takahashi.presentation_preferences`.
- Classification: adjustable, never a replacement for `takahashi.text_primary`.
- Evidence class: project synthesis / user-selected preference, not a creator rule.
- Basis: the accepted specification's non-core/core boundary and the existing
  [core/source record](core-rule.md). T1 supports large textual emphasis; limited
  T2 observations prevent a universal ban on other forms. Neither establishes an
  official adjustable menu, chart count, color palette or numerical threshold.
- Reading limits: reuse the core record's publisher-introduction and extracted
  sample-text scopes. No full-book, full-video or rendered-slide validation added.

## Required propositions and conditions

Apply this record only to requested compatible presentation preferences, including
appearance or supporting-detail choices. State the actual accepted preference in
both Markdown and constraint; preserve its supplied conditions. Words remain the
primary visual/message carrier, relative scale establishes their priority, and any
other detail supports rather than equals or dominates the text. Preserve necessary
material qualifications. This record is optional when no preference is applicable;
it does not require charts, notes, colors or any fixed count by default.

A chart and three note lines explicitly supporting the main words are a compatible
example. Three reflects that request, not a universal allowed-count rule. A color
preference can also be compatible if it retains the core relationships. In contrast,
letting a dense chart become primary while words become a minor heading conflicts
with the core. Removing a qualification needed for interpretation is also incompatible.
These are semantic guidance judgments, not a rendering or rewriting procedure.
